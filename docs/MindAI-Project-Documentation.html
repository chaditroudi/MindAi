1. What Does the App Do?

One-Sentence Summary Mind Analytics Console is an AI-powered analytics platform for municipal government data — you type a question in Arabic or English, and the system automatically queries the database and gives you a chart, a report, or search results.

The platform is designed for municipal managers and analysts who work with government data. They do not need to know SQL or any database language. They simply ask questions in natural language and the AI handles the rest.

The app is built specifically for Qatar municipalities (tenant: t_mind_qatar) and supports both Arabic and English prompts.

3. Data It Works With

MongoDB CollectionWhat It Contains

inspectionsField inspection records
permitsConstruction and building permits
projectsMunicipal project records
data_storesMetadata about the above collections (field names, types, roles)
conversation_memoryChat history for follow-up questions

Each data collection has a data store definition stored in data_stores. This definition tells the app what fields exist and their roles:

  • dimension — a category to group by (e.g. municipality, serviceType)
  • measure — a number to calculate (e.g. cost, duration)
  • temporal — a date/time field (e.g. createdAt)

4. How It Works — Step by Step

Dashboard Example: "Top 5 cities by service request count"

StepWho Does ItWhat HappensOutput
1. Receive Express API Request arrives at /api/dashboard, input is validated Clean input object
2. Plan Supervisor Agent (AI) Reads the prompt and decides: which collection? count or sum? which dimension? top N? TaskPlan JSON: { dataStoreName: "ServiceRequests", aggregation: "count", dimensions: ["municipality"], topN: 5 }
3a. Query MongoDB Runtime Builds a MongoDB aggregation pipeline from the plan, runs it against the database Rows: [{ municipality: "Doha", count: 1200 }, ...]
3b. Enrich Search Agent (AI) If the supervisor requested enrichment, searches internal documents in parallel Extra context rows (or empty)
4. Merge Merge Tool Combines MongoDB data + enrichment data on a shared key (e.g. municipality) Merged dataset
5. Chart Chart Planner (AI) + Chart Tool AI decides chart type and axes. Deterministic builder generates the ECharts config Complete ECharts option object + Arabic title
6. Respond Express API Returns the chart JSON to the browser Browser draws the chart
Note: Steps 3a and 3b run at the same time (parallel) The MongoDB query and the internal search run simultaneously to save time. They are merged in Step 4.

5. Every File Explained

Entry Point

src/server.ts

What it is: The on/off switch of the whole app. When you run npm run dev, this file starts the web server on port 3000. It opens the door and routes /api/* requests to the router. Nothing intelligent happens here.

Web Layer — src/http/

src/http/api-router.ts

What it is: The traffic cop. Reads the URL and sends each request to the right handler. Also catches errors and returns Arabic error messages. Handles 4 routes: /inquiry, /report, /dashboard, /meta.

src/http/contracts.ts

What it is: The rulebook for every request and response. Defines the exact shape of data — what fields are required, what types. If a request doesn't match the template it gets rejected immediately before any AI is called.

Brain — src/services/

src/services/analytics-service.ts

What it is: The main coordinator — the most important file. When a request arrives it: checks if it is a follow-up question, starts the right Mastra workflow, waits for the result, saves the conversation to memory, and returns the final answer. It also generates the auto-suggestions you see in the UI by reading actual data stores.

src/services/conversation-memory.ts

What it is: The app's short-term memory. Every question and every answer gets saved to MongoDB. When the user asks a follow-up like "same but for last year", this file loads the last 8 turns of conversation so the AI understands context. Stores: who asked, what they asked, what the answer was, and when.

Workflows — src/mastra/workflows/

These are the assembly lines. Each workflow is a series of steps that run in a defined order.

src/mastra/workflows/dashboard.ts

5 steps: Plan → Query + Enrich (parallel) → Merge → Chart. Returns a single ECharts chart.

src/mastra/workflows/report.ts

5 steps: Plan → Query + Enrich (parallel) → Merge → Write. Returns Arabic narrative sections + optional chart.

src/mastra/workflows/general-question.ts

3 steps: Plan → Query + Enrich (parallel) → Write. Returns a short summary + record links.

AI Agents — src/mastra/agents/

Each agent is an AI brain with specific instructions. They are specialists that handle one job each.

src/mastra/agents/supervisor.ts

Job: Read the user's question and create a structured plan. Decides: which data store? count or sum or average? which dimension to group by? any filters? top N? Outputs a TaskPlan JSON object.

{
  "intent": "dashboard",
  "needsData": true,
  "needsChart": true,
  "query": {
    "dataStoreName": "ServiceRequests",
    "aggregation": "count",
    "dimensions": ["municipality"],
    "topN": 5
  },
  "chartHint": "ranking"
}

src/mastra/agents/mongodb.ts

Job: Execute the database query safely. Uses tools to find the right data store, build the aggregation pipeline, run it, and return clean rows. It is read-only — can never create, update, or delete data.

src/mastra/agents/chart.ts

Job: Decide how to visualize the data. Sees only the data schema, up to 3 sample rows, row count, prompt, and Supervisor hints (never the full dataset). Decides: which chart type? which field on X axis? which on Y? Outputs a chart plan that gets validated before rendering.

src/mastra/agents/writer.ts

Job: Write the Arabic report text. Takes the data rows and writes human-readable analytical sentences organized into sections with headings.

src/mastra/agents/search.ts

Job: Search internal documents. Only activated when the Supervisor sets needsEnrichment=true. Searches exported database files or vector embeddings for related context. Never searches the web.

Runtime Adapters — src/mastra/runtime/

These files are the connectors between workflow steps and agents. Each one calls an agent, handles timeouts, and cleans up the output.

FileWhat It Does
supervisor-runtime.tsCalls the Supervisor agent. Loads data stores, sends everything to AI, parses and validates the plan.
mongodb-runtime.tsCalls MongoDB tools. Finds the data store, builds pipeline, runs it, returns clean rows.
chart-runtime.tsCalls the Chart Planner agent for non-empty chart datasets. Sends schema, up to 3 sample rows, row count, prompt, Supervisor hints, and candidate chart types. Gets a chart plan, validates it, then passes it to the ECharts builder.
writer-runtime.tsCalls the Writer agent to generate Arabic report sections.
search-runtime.tsCalls the Search agent when enrichment is needed.
llm-queue.tsA queue that prevents too many AI calls at once. Like a waiting room.
timeout.tsSets time limits on every AI call. Cancels and returns error if AI hangs.
json-output.tsCleans the AI response — extracts the JSON from any surrounding prose.

Tools — src/mastra/tools/

Tools are functions that agents can call to do real work.

src/mastra/tools/mongodb-tools.ts

Contains 3 functions: buildAggregation (convert plan to pipeline), executePipeline (run against database), validateRows (clean results).

src/mastra/tools/chart-tools.ts

Contains buildChartFromDataset — takes a validated chart plan and dataset, produces the complete ECharts option object that the browser uses to draw the chart.

src/mastra/tools/search-tools.ts

Contains vectorSearch — searches internal documents by semantic embedding (if set up) or by simple text matching over the exported JSON sample files.

src/mastra/tools/merge-tools.ts

Merges two datasets into one by joining on a shared key (e.g. municipality). Used when MongoDB results and Search Agent results need to be combined.

Analytics Query Builders — src/analytics/builders/

These files convert the AI's TaskPlan into a real MongoDB aggregation pipeline, stage by stage.

FileMongoDB StageWhat It Does
build-pipeline.tsAssemblerCalls all builders below in the correct order, returns the complete pipeline
build-match-stage.ts$matchFilters rows — by tenantId (security), status, date range, any filter from the plan
build-lookup-stage.ts$lookupJoins with another MongoDB collection when needed
build-group-stage.ts$groupGroups rows and counts / sums / averages the values
build-having-stage.ts$match (post-group)Filters after grouping — like SQL HAVING clause
build-project-stage.ts$projectPicks which fields to return and renames them cleanly
build-percent-stage.tsCustom stagesCalculates percentage values from totals
build-sort-stage.ts$sortOrders results highest to lowest (or by date)
build-limit-stage.ts$limitReturns only the top N results

Validators — src/analytics/validators/

Check the AI plan before building the pipeline — ensures field names are real, filters are valid, time ranges are properly formatted, and the tenant scope is respected.

FileWhat It Validates
validate-scope.tsUser has permission to access this data store
validate-task-plan.tsOverall plan structure is complete and coherent
validate-metrics.tsMetric fields are real numeric fields in the data store
validate-dimensions.tsDimension fields exist and are valid grouping fields
validate-time-fields.tsDate/time fields and ranges are valid
validate-lookups.tsJoin references are valid

Database Layer — src/db/

src/db/mongo.client.ts

Opens and manages the single MongoDB connection. Reused across the whole app — only one connection is created.

src/db/datastore.repository.ts

Loads data store definitions from the data_stores MongoDB collection. Caches them in memory so the database is not hit on every request. Provides two methods: findDataStore(name) and listAccessibleDataStores(scope).

The UI

public/index.html

One single HTML file — the entire frontend. Contains:

  • Left panel: mode tabs (Dashboard / Report / Inquiry), text area, run button, auto-generated suggestions
  • Right panel: the chart or report result
  • Audit section: shows the AI plan, MongoDB pipeline, field schema, and response time
  • Live progress bar with Arabic stage labels while the request runs
  • All JavaScript embedded in the same file using ECharts for drawing
  • Conversation state tracked so follow-up questions work

Config, Model & Other Files

src/mastra/model.ts

Decides which AI model to use by reading the .env file. Supports two providers and allows each agent to use a different model. Default is Llama 3.3 70B via OpenRouter (free) or Groq (faster).

src/config/review-catalog.ts

Defines the 3 mode descriptions shown in the UI, the capability matrix (what is done vs. planned), and the Search Agent capability cards.

src/mastra/index.ts

Registers all agents and workflows with the Mastra framework so they can be retrieved by name at runtime.

src/mastra/task-plan.ts

After the Supervisor AI returns a plan, this file finalizes it — fills in any missing fields, corrects the intent, and ensures the plan is valid before the workflow continues.

8. What Is Done vs. Planned

Done — Fully Working
  • All 3 modes: Dashboard, Report, Inquiry
  • Registered agents: Supervisor, MongoDB contract, Chart Planner, Writer, Search
  • Deterministic MongoDB aggregation pipeline builder
  • ECharts rendering (line, bar, horizontal bar, donut, histogram, scatter, map)
  • Conversation memory for follow-up questions
  • Auto-generated prompt suggestions from real data
  • Multi-tenant permission scope (tenantId filtering)
  • Parallel workflow execution (query + enrich run at same time)
  • Full audit trail in the UI (AI plan, MongoDB pipeline, schema, timing)
Planned — Not Yet Built
  • NestJS gateway and Angular full frontend shell
  • Real-time streaming progress (show AI thinking live)
  • Semantic vector search (requires embedding index setup)
  • Geographic map charts with configured region data
  • Authentication-injected permission scope (currently hardcoded)
  • Create / Update / Link operations (currently read-only)
  • External data enrichment providers
  • Nx monorepo workspace setup
