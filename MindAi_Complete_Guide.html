Project Architecture

MindAi is a two-layer application: an Angular frontend (client/) that talks to a NestJS backend (nest-app/) which orchestrates LLM calls and MongoDB queries.
FolderTechnologyPurpose
client/Angular 18Browser UI — prompt input, chart display, session history
nest-app/NestJS + MongooseMain backend — REST API, LLM calls, MongoDB
skills/Markdown filesAI system prompts loaded at runtime
src/Express + MastraLegacy parallel backend (same features, older pattern)
data/SQLite (LibSQL)Conversation session storage (Mastra Memory)
Browser → Angular (client/)
Angular → POST /api/analytics
NestJS → AnalyticsController → AnalyticsService
→ PipelineService → planner.ts (LLM #1: MongoDB pipeline)
→ MongoDB.aggregate(pipeline)
→ chart.ts (LLM #2: widget plan)
→ writer.ts (LLM #2: text response)
→ Response sent to browser ✅
→ [background] memory-skill.ts (LLM #3: extract memory)
→ [background] embeddings.ts (local: save vector)

1 — Startup Files

01main.ts57 lines
nest-app/src/main.ts
Entry point — boots the NestJS server

This file runs first when you type npm run start. It creates the NestJS application and configures it before opening the HTTP port.

What it does step by step

// 1. Create the app from AppModule
const app = await NestFactory.create(AppModule)

// 2. Set our custom colored logger
app.useLogger(app.get(AppLogger))

// 3. Security headers (helmet) — blocks XSS, clickjacking, etc.
app.use(helmet({ contentSecurityPolicy: false }))

// 4. CORS — which domains can call this API
app.enableCors({ origin: allowedOrigins })

// 5. Auto-validate request bodies using class-validator decorators
app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }))

// 6. Start listening on PORT (default 3000)
await app.listen(port)

// 7. Start loading the 25MB embedding model in the background
warmupEmbeddings()
warmupEmbeddings(): The local AI model for semantic memory takes 2-3 seconds to load. By calling it here at startup, the first user query doesn't have to wait for it.

Root module — wires all modules together and registers global providers

In NestJS every feature lives in a Module. AppModule is the root module that imports all others. Think of it as the main electrical panel — every circuit connects here.

// Step 2: Check data sources exist

14pipeline.service.ts423 lines
nest-app/src/analytics/pipeline.service.ts
MongoDB execution engine — runs LLM-generated pipelines with retry and validation

Three public methods

MethodIntentCalls
executeDashboard()dashboardaggregate() → runChart()
executeReport()reportaggregate() → runReportSkill() → runChart()
executeInquiry()general_questionaggregate() → runInquirySkill()

The retry loop inside aggregate()

for (attempt = 0; attempt < 2; attempt++) {
  plan = await runSupervisorPlan({...hint})  // LLM generates pipeline

  try {
    validatePipelineFields(plan.pipeline, source) // check field names
    rows = await runAggregation(collection, pipeline) // run MongoDB
  } catch (err) {
    hint = `Field validation failed: ${err.message}. Check field names...`
    continue  // retry with hint injected into prompt
  }
}

Security — blocked pipeline stages

// These MongoDB stages are blocked (could modify or expose data):
const FORBIDDEN_STAGES = { '$function', '$merge', '$out', '$where', '$eval' }
// If LLM generates one → throws BadRequestException before running
Why validate fields? LLMs hallucinate field names. If we send a pipeline with "$sort": { "budjet": -1 }, MongoDB silently ignores it and returns all records unsorted. Validation catches this and retries with a hint to the LLM.
